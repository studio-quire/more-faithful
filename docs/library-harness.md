# The conflict harness

Claude Opus 5.5, 2026-11-04. How the Faithful Library's mods are tested against each other, stage by stage, and what it doesn't reach. Writing a mod's own test: `docs/library-authoring.md` > Testing.

Stages, cheap first:

1. **Static**, no game. Every jar: nothing outside `assets/<modid>/` and its own package; no `@Overwrite`; every reference from common code resolves on the server jar (client-only
   members are the classic crash); direct reads of `Chunk.blocks`/`meta` and hand-rolled stack comparisons flagged; every mixin target listed, the editions' jars read too. Methods more than one mod changes are
   listed as information, since mods sharing a method is normal (user, 2026-11-08: a list of accepted pairs failing until someone signs off grew with every mod). Two `@Redirect`s on one site always fail, as both can never apply. Built: `./gw :harness:libraryStatic` over named jars, the game's side
   marks from the merged jar, a `client` package or a config's `client` list counting as client code (and likewise `server`, since a server-only reference crashes a client). A method marked `@Environment` is on that side whatever its class is, as Fabric strips it from the other, and client and server code are held to their own side too. Mods' `selftest` jars get the side rules alone: common code is what `faithful:mod` and `faithful:test` reach, client code what `faithful:client` and `faithful:test-client` reach, and a class marked or in a `client` or `server` package is that side's. The core keeps only the jar and mixin rules, and isn't counted among the mods sharing a method: it's the hook.
   Every target is listed in `harness/build/reports/library-static.txt`. `libraryStaticBadTest` runs the rules over a jar of planted mistakes.
2. **Registry**, one server boot and a hidden client. Names lowercase and in the mod's namespace; every block with an item and every item a lang name (a `noItem` block is never named on screen), every tile a 16x16 PNG or a strip of them (the atlas animates a strip, two ticks a frame); stand-ins real and safe in a
   vanilla reader's world (no fire, no flowing liquid); a block's tiles in one atlas, every side and meta 0-15 (`tiles-in-one-atlas`); block items stand in as something vanilla really gives (lit variants and crops declare `noItem`); blocks and items outside the
   registry (`unregistered-block`, `-item`); tags against `library/tags.txt` (`tag-vocabulary`); each mod recipe laid out in a real grid and every recipe in the game asked, so a clash with vanilla's counts (`two-recipes-one-shape`), and what recipes name exists.
   Commands that shadow the server's own. Duplicate channels, rules, commands and blocks stop the game as it starts, read back as `declared-twice` with the mod; settings registered twice are the settings screen's warning. Duplicate default keys are listed, not failed. The probe also forces Mixin's audit, so every target applies.
3. **Combinations.** Each mod alone (with what it depends on), the core alone, everything together, seeded half-sets until every pair has met with some third absent, a client logging in to each, one game at a time unless `-Plibrary.parallel=N` says otherwise (the PC is shared); hidden clients on the whole set and two half-sets.
   Then the **edition axis**: Pure, Old and Still's mods under the set, client and server, as they ship and with every boolean in `oldfaithful-*` and `stillfaithful-*` config files turned over, then each edition's client on each edition's server. A client there runs only the mods' world checks (`worldChecksOnly`), since the editions' own expect their switches as shipped.
   **Selftest**, a stage of its own after this one (`selftest`, or `./gw :harness:librarySelftest -Plibrary.mods=a,b` alone, where only the named mods' tests run and what they depend on comes along): each subject's `src/selftest`, or a test mod's own `faithful:test` entrypoints, all in one world, each on a plot of its own: single player, reopened, a real server with a hidden client joined, restarted. A mod's `WorldTest` runs where the world runs, told to start over `harness-probe:test`, then its `ClientTest`; the API is in `library/harness-probe/.../harness/test`, and how to write one in `docs/library-authoring.md` > Testing. `[faithful-test] FAIL mod | what` on either side fails as `selftest`, and a mod with a test that reports no passes on first run in either place fails as `selftest-no-checks`. A set with content then joins a server with the core alone and the real server, which admit it, and runs each mod's `faithful:test-without` there.
4. **Salts**: the numbering and the mods' order shuffled, so a mod that relies on either shows up. The arena (one of everything, `Arena`: every mod block at metas 0, 1, 7, 15, every item in chests, on the floor and in a player's inventory with stack data, every mod entity) reopened with every mod block and item under another number (`numberSalt`) and compared by name (`number-salt`). Whole numbers a mod saved are weighed against both numberings
   (`number-in-nbt`), and so are its static ints, by reflection (`number-in-static`). Order salts, shuffled orders in which mods' hooks run, are chosen to turn every pair of mods round (`Core.orderKey`, worked out in the task); a fixed list of acts with their randomness seeded (every block broken by hand and pick, every mod item used, every mob killed) is compared against two plain runs,
   so the game's own chance doesn't count (`order-matters`, naming the mods sharing a hook). Explosions aren't in the list: their rays have a `Random` no seed reaches. Vanilla's **tables** (blocks, items, tools, recipes, smelting, fire, entities, spawn lists): each mod alone against the core alone is listed in `tables-changed.txt`; two mods changing one entry differently fails (`two-mods-one-table-entry`), and so does an entry that's different together (`changes-together`), unless `library/together.txt` declares it: two of our mods meeting by design, at that value and with every mod it names (World Rules' worn bows and Item Repair's mending, 2026-11-10), a note then.
5. **Round trips.** The arena saved and reloaded twice, equal (`round-trip`; a cell whose meta alone moved is a note, as a block entity may do that). No block ticks in an arena world (`WorldFrozenMixin`): it's no place for a crop or a leaf to live, and a change should mean the save did it. Each content mod removed, then all of them: the server refuses and says how to go on, then the cells read as their stand-ins, and they're back when the mod returns. The warning screen on a real client, reached through the real world list,
   drawn and read, **Make a Backup and Play** clicked, the backup there, the world running. The world opened by the **real, unmodified server**, joined by a raw client, saved.
6. **Multiplayer.** A generated must-match mod makes refusal testable on any set. A real hidden client with the same mods (admitted), missing one, with an extra, at another network version, and with no core, each ending on a screen whose drawn text is checked (`TextRendererRecordMixin`, pictures in `shots/`). `RawClient` then sends twelve shapes of bad reply to the hello, and nine shapes of message on every channel in the hello
   (empty, zeros, all ones, a length of two thousand million, noise up to 32 KB), reconnecting when kicked: the server must keep answering and a bystander must stay (`channel-hangs-server`, `channel-drops-bystander`, `crash`), and a handler that runs out of memory or stack is a kick for that peer and a failure for its mod (`channel-handler-overran`). A kick for garbage is the design and isn't a failure. Then `RawServer`, playing a real server's hello to a real hidden client with the same mods: the same bad hellos, 250s with bad lengths and prefixes, noise on every channel, and with content bad overlay ids, short and long tails, bad 52s and 53s, bad stack data. The client must disconnect where it's marked, and always stop cleanly.
7. **The monkey**, a scripted player using everything on everything, as in monkey testing (`client/Monkey`, `MonkeyServer`, `MonkeyState`). On a real client and server: benches of up to 24 blocks, set by the server around the player; the item used on each through `InteractionManager`; mod items on mod blocks, mining with a pick, mod items on vanilla blocks, then vanilla items on mod blocks, until a budget of 6,000 ticks, five minutes (`-Plibrary.monkeyTicks`; a note says if it ran out).
   After each, both sides build the same lines (`MonkeyState`: cells, inventory, cursor, screen slots, entities); what's still different on a second look fails as `ghost-block`, `inventory-differs` or `entity-differs`. A screen that opens is clicked: every slot shifted, random left and right clicks, every slot shifted again, and the items in it must not grow (`item-count-grew`). **`harness:scenario`** (`Scenario`): a mod's own short test, a `Scenario` entrypoint, run in single player and on a server.
8. **`coreInertTest`** (`./gw :harness:coreInertTest`, not part of `libraryTest` unless named: it doesn't change with the mods). A fixed seed and spawn, saved before the first tick, chunk bytes with the core against without, after two plain runs show what repeats; a scene's pixels likewise, with lava, water and particles held still (they animate by chance, and a pixel can agree between two plain runs by luck), and anything that still varies taken out, with what's beside it, a difference having to last through up to three more plain runs as a flow of lava stands differently each time; a client without the core on a server with it, one with it on the real server.

`./gw :harness:libraryTest` runs `libraryStatic`, then stages 2 to 7 on every shipped mod or a set (`-Plibrary.mods=a,b`, any folder in `library/`), stopping at the first stage that fails. `-Plibrary.stages=registry,monkey`, `-Plibrary.keepGoing`, `-Plibrary.seed=N`, `-Plibrary.monkeyTicks=N`. A failure reads `stage: mod: rule: detail`, all of them in `report.txt` in the run folder, so an agent can act alone. The game's side of it is `library/harness-probe`, a test-only mod in every run.

`./gw :harness:libraryBadTest` is how the harness is tested: `library/fixture-bad-one`, `-two` and `-monkey` hold a mistake for each rule, each on when `-Dfaithful.bad` names it, and every one must be reported against the right mod. `library/fixture-ore`, `fixture-machine` and `api-check` are honest mods for it to pass: `-Plibrary.mods=fixture-ore,fixture-machine,world-rules,api-check` is the run to use, since the default set is World Rules alone, with no content for most stages to chew on. `api-check` is what brings block entities, entities and screens to the arena and the monkey; its own client check runs only under `libraryApiTest` (`-Dapicheck.clients`). A new rule gets a planted mistake.

`fixture-ore`'s is the one honest mod's test left for the selftest stage to run, on one plot, so nothing there shows two mods' tests sharing a world any more. A selftest that's client-only and declares content is left out of runs on a server, as it can't join one.

Beta's own quirks the monkey allows for, so they aren't reported against a mod: it treats still and flowing liquid as one, as beta swaps them with no block update (`convertToFlowing`, `convertToSource`), and walls its bench, so nearby water can't flood it. A screen that opens mid-bench is closed before the bench's next use, and the monkey waits for two answers from the server first: on the tick after another screen closes, beta resends the slots of the player's own screen as they were before that one opened, and a use in between would leave one item too many on the client for good. The default budget doesn't reach every bench of a large set (32 of 191 on the run above), mods against mods and mining first.

What the harness has to work on is thin now. With no content mods, combinations, salts and the monkey meet only test mods, whose blocks do little in play, so a clean run says the machinery works, and little about real mods together.

Shallow, for now: the monkey doesn't count screens with an output slot (a slot that refuses dirt), as making things changes totals fairly, so a dupe through one goes unseen; it uses items on blocks, not on entities; a hostile server's attacks on modded screens are noise on `core:` channels only, not crafted ones; the number checks see what the arena's fresh blocks saved, not state a mod only reaches in play; the real server's run checks it loads, runs and saves, while what it read is checked on the core's side.
